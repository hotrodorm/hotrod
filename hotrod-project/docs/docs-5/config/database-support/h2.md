# Support for H2 Database

The HotRod H2 dialect rules automatically map common database column types to application types.

If your application needs to use a different type that differs from the dialect rules, you can override
it by directly designating for a column, or by the use of general type solver rules. See [Full Type Solver Precedence](../full-type-solver-precedence.md) for details on how to override the  default dialect types.

## 1. Static Dialect Rules

The Static Dialect Rules are used to compute the types of properties used in the application to retrieve data from the database. These types are computed during the generation of the persistence layer; the types decided at this opportunity are set in stone and cannot be changed at runtime.

The following table shows rules that are used to map the column types in the database to the types you see in your app.

The rules are denoted using the symbol :small_orange_diamond: followed by the rule ID; for example, "D4" means "Static Dialect Rule #4". The rule IDs are included as comments in the properties of the layout classes, and also in the LiveSQL queries (when logging). They describe which rule exactly was used to compute the data type for a column.

| `TINYINT` | `java.lang.Byte` :small_orange_diamond:D7|

## 2. Runtime Dialect Rules

The Runtime Dialect Rules are used to compute the types of LiveSQL expressions when retrieving data from the database using SELECT queries.

These rules are not used if a LiveSQL was explicitly designated a type or converter using `.type(<class>)`; they are not used either if a Runtime Type Solver rule matched this column and decided on the column type or converter. These two have precedence over the Runtime Dialect Rules.

These rules affect only LiveSQL expression; LiveSQL table or view columns &ndash; such as `a.balance` where `a` is a table or view &ndash; are not affected since their types were already computed in a static manner during the persistence layer generation.

The following table shows rules that are used to map the column types in the database to the types you see in your app.

The rules are denoted using the symbol :small_orange_diamond: followed by the rule ID; for example, "RD3" means "Runtime Dialect Rule #3". The rule IDs are shown in the LiveSQL queries (when logging). They describe which rule exactly was used to compute the data type for a column.

| `TINYINT` | `java.lang.Byte` :small_orange_diamond:D7|
